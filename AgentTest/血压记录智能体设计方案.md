# 血压记录智能体设计方案

## 一、需求分析

### 1.1 业务需求

设计一个多轮会话智能体，能够：
- **友好引导**：通过自然对话引导用户填写血压数据
- **数据收集**：收集血压的关键信息（收缩压、舒张压、测量时间等）
- **数据验证**：验证用户输入的血压数据是否合理
- **数据存储**：将收集到的血压数据持久化存储
- **会话管理**：支持多轮对话，能够记住上下文和历史记录
- **异常处理**：处理用户拒绝、跳过、修改等场景

### 1.2 功能需求

#### 1.2.1 核心功能

1. **血压数据收集**
   - 收缩压（Systolic Pressure）：正常范围 90-140 mmHg
   - 舒张压（Diastolic Pressure）：正常范围 60-90 mmHg
   - 测量时间：用户测量血压的时间
   - 备注信息：用户可选的额外信息（如：运动后、服药后等）

2. **对话引导流程**
   - 主动问候并说明目的
   - 逐个询问血压数据项
   - 确认收集到的数据
   - 提示保存成功

3. **数据验证**
   - 验证血压数值是否在合理范围内
   - 验证数据格式是否正确
   - 提供友好的错误提示和重新输入建议

4. **数据持久化**
   - 将血压记录存储到长期记忆（PostgreSQL Store）
   - 支持历史记录查询
   - 支持数据更新和删除

#### 1.2.2 辅助功能

1. **历史记录查询**
   - 查询用户的历史血压记录
   - 按时间范围查询
   - 统计分析（平均值、趋势等）

2. **数据修改**
   - 允许用户修改已保存的血压记录
   - 确认修改操作

3. **会话恢复**
   - 支持中断后恢复对话
   - 记住已收集的数据项

### 1.3 非功能需求

1. **性能要求**
   - 响应时间 < 3秒
   - 支持并发用户会话

2. **可靠性要求**
   - 数据持久化不丢失
   - 异常情况下的友好提示

3. **用户体验要求**
   - 对话自然流畅
   - 提示信息清晰明确
   - 支持多种表达方式输入

### 2.3 工具设计

#### 2.3.1 记录血压工具（record_blood_pressure）

**功能**：保存用户输入的血压数据到长期记忆

**参数**：
- `systolic`: int - 收缩压
- `diastolic`: int - 舒张压
- `timestamp`: str - 测量时间（可选，默认当前时间）
- `notes`: str - 备注信息（可选）

**返回值**：
- 成功：返回保存成功的消息和记录ID
- 失败：返回错误信息

**验证规则**：
- 收缩压范围：90-250 mmHg
- 舒张压范围：60-150 mmHg
- 收缩压必须大于舒张压
- 时间格式验证

#### 2.3.2 查询血压记录工具（query_blood_pressure）

**功能**：查询用户的历史血压记录

**参数**：
- `start_date`: str - 开始日期（可选）
- `end_date`: str - 结束日期（可选）
- `limit`: int - 返回记录数量限制（可选，默认10）

**返回值**：
- 返回符合条件的血压记录列表

#### 2.3.3 更新血压记录工具（update_blood_pressure）

**功能**：更新已存在的血压记录

**参数**：
- `record_id`: str - 记录ID
- `systolic`: int - 新的收缩压（可选）
- `diastolic`: int - 新的舒张压（可选）
- `timestamp`: str - 新的测量时间（可选）
- `notes`: str - 新的备注（可选）

**返回值**：
- 成功：返回更新成功的消息
- 失败：返回错误信息

### 3.5 工具调用上下文传递

由于工具需要访问 `store` 和 `user_id`，需要修改工具调用方式：

**方案1：使用工具参数传递**
- 在工具定义中添加 `store` 和 `user_id` 参数
- 在调用时传递这些参数

**方案2：使用全局上下文**
- 将 `store` 和 `user_id` 存储到全局上下文
- 工具从全局上下文读取

**方案3：修改工具实现方式**
- 创建一个工具工厂函数
- 接收 `store` 和 `user_id` 作为参数
- 返回配置好的工具实例

**推荐方案3**，因为它更符合函数式编程范式，且易于测试。

### 4.4 数据验证增强

在工具中添加更详细的数据验证：

```python
def validate_blood_pressure(systolic: int, diastolic: int) -> tuple[bool, str]:
    """
    验证血压数据
    
    Returns:
        (is_valid, message): 验证结果和消息
    """
    # 范围检查
    if not (90 <= systolic <= 250):
        return False, f"收缩压 {systolic} mmHg 超出合理范围（90-250）"
    
    if not (60 <= diastolic <= 150):
        return False, f"舒张压 {diastolic} mmHg 超出合理范围（60-150）"
    
    # 逻辑检查
    if systolic <= diastolic:
        return False, f"收缩压 {systolic} 必须大于舒张压 {diastolic}"
    
    # 健康提示
    warnings = []
    if systolic > 140:
        warnings.append("收缩压偏高，建议关注")
    if diastolic > 90:
        warnings.append("舒张压偏高，建议关注")
    if systolic < 90:
        warnings.append("收缩压偏低，建议关注")
    if diastolic < 60:
        warnings.append("舒张压偏低，建议关注")
    
    warning_msg = "。".join(warnings) if warnings else ""
    
    return True, warning_msg
```

    assert "舒张压" in response.lower()
    
    # 3. 用户提供舒张压
    response = await invoke_agent("80")
    assert "时间" in response.lower()
    
    # 4. 用户提供时间
    response = await invoke_agent("今天早上8点")
    assert "确认" in response.lower()
    
    # 5. 用户确认
    response = await invoke_agent("是的")
    assert "保存" in response.lower() or "成功" in response.lower()

# 测试用例2：数据验证
async def test_validation():
    # 测试不合理数据
    response = await invoke_agent("收缩压200，舒张压80")
    assert "偏高" in response.lower() or "确认" in response.lower()

async def test_all_at_once():
    response = await invoke_agent("我今天早上8点测量了血压，收缩压120，舒张压80")
    assert "确认" in response.lower()
